# `.cursorrules.md`

## 🚨 CORE PRINCIPLES (Non-Negotiable)

* **Never reinvent components** — always reuse existing UI components from `components/ui` or the design system.
* **Never introduce new colors, fonts, spacing scales, shadows, or radii** outside the defined design tokens.
* **Never generate inline styles** unless absolutely required.
* **Never hardcode values** that exist in Tailwind config (colors, spacing, typography, breakpoints).
* **Never mix styling approaches** (NO CSS modules if Tailwind classes are enough).
* **Always maintain semantic HTML**.
* **Always keep accessibility in mind** (proper headings, alt text, ARIA attributes).
* **Mobile-first. Always.**

---

## 🎨 DESIGN SYSTEM ENFORCEMENT

### Colors

* Use only the color palette defined in `tailwind.config.js`.
* If a new color is needed → STOP → do not create it. Use the closest existing token.
* Never use hex values directly. Only use semantic colors like:

  * `text-primary`
  * `bg-secondary`
  * `border-muted`
  * etc.

### Typography

* Use the project's defined font families and sizes.
* Never manually set `text-[14px]` unless it's a defined scale.
* Follow heading hierarchy strictly:

  * `h1` → max page title
  * `h2` → primary section title
  * `h3` → subsection
* Avoid excessive bolding and random font weights.

### Spacing & Layout

* Use Tailwind spacing scale only.
* Follow consistent spacing patterns:

  * Section padding: `py-16 md:py-24`
  * Container width: `max-w-7xl mx-auto px-4 md:px-6`
* Consistent gap usage for flex/grid:

  * `gap-4`, `gap-6`, `gap-8` only.

### Components

* Prefer composition over large page components.
* Every repeated UI pattern MUST be a component:

  * Buttons
  * Cards
  * Feature blocks
  * Pricing blocks
  * Testimonials
  * Hero sections
* Components must be:

  * Accessible
  * Responsive
  * Reusable
  * Clean

---

## 📱 RESPONSIVE & GRID RULES

* Mobile-first layout.
* Important breakpoints:

  * `sm` = basic grid
  * `md` = split layout
  * `lg` = desktop enhancements
* Follow these defaults:

  * For grids:

    * `grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-3`
  * For hero sections:

    * `flex flex-col md:flex-row items-center`

## ⚛️ NEXT.JS BEST PRACTICES

### File Structure

```
/app
  /components
  /sections
  /layouts
  /lib
  /hooks
  /styles
  /config
  /data
```

* Pages should contain **minimal logic**.
* Complex UI must be inside `/components` or `/sections`.

### Server & Client Components

* Use **Server components** by default.
* Use **Client components only** when needed:

  * state
  * hooks
  * interactivity (menus, sliders, forms)

### SEO

* Always use Next.js `metadata` API.
* Add `openGraph` and `twitter` configs.
* Every page must have:

  * `<h1>`
  * meta description
  * structured content hierarchy

### Image Usage

* Always use `<Image>` from `next/image`.
* Always provide alt text.
* Never hardcode width/height unless necessary.
* Use responsive images.

---

## 🧩 COMPONENT QUALITY RULES

Each component must:

* Use Tailwind classes only.
* Be structured, readable, and maintainable.
* Follow consistent naming:

  ```
  ComponentName.tsx
  ```
* Accept props instead of hardcoded strings.
* Provide default props where appropriate.
* Use slots/children for flexible content.

---

## 🧼 CODE STYLE & CLEANLINESS

* No commented-out code.
* No unused imports.
* No random utility classes — keep class sets clean.
* No magic numbers.
* Keep files under 200 lines when possible.

---

## 🎯 DESIGN CONSISTENCY RULES

Every page MUST follow:

* A consistent grid.
* A balanced vertical rhythm (spacing).
* No random shadows or borders.
* All buttons must come from a shared `Button` component.
* All icons must come from a shared icon library (Lucide / Heroicons).
* All text scale must follow the design tokens.

---

## 🧱 UI/UX BEST PRACTICES

* Clear hierarchy: big title → description → CTA → visuals.
* Each section should have:

  * **Purpose**
  * **Consistent padding**
  * **A clear focal point**
* Avoid clutter.
* Avoid too many colors.
* Avoid overly large text on mobile.

---

## 💾 PERFORMANCE RULES

* Never import full libraries — import only needed components.
* Use Next.js optimizations:

  * dynamic imports
  * caching
  * image optimization
* Avoid re-renders in client components:

  * memoize when necessary
  * avoid anonymous functions inline if they cause re-renders

---

## 🛡️ ERROR-PROOFING RULES

* For any feature:
  If a similar component or structure already exists → ALWAYS REUSE IT.
* If a new design pattern is introduced → REJECT and ask for approval.
* If colors/typography don’t match the design system → REJECT.
* If spacing looks inconsistent → FIX.
* If component is bloated → REFACTOR.

---

## 💬 AGENT BEHAVIOR RULES

When generating code:

* Follow all rules above.
* Never hallucinate new design elements.
* Never create unnecessary files or folders.
* When unsure → follow the existing patterns.
* Always prioritize:

  1. Consistency
  2. Reusability
  3. Clean architecture
  4. Accessibility
  5. Performance

If the request breaks any rule → refuse and propose a corrected approach.
